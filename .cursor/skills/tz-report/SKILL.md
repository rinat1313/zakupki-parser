# Подготовка отчётов (этап 8)

Skill **дополняет** `tz-workflow`. Не заменяет его. Не дублирует 8 этапов и не создаёт второй workflow.

## Когда включать

После успешного пакета этапа 7 (`tz-docs`: документы актуальны или явный N/A) и успешной проверки этапа 6. `lead` читает этот skill **до** закрытия ТЗ.

Не основной сценарий для этапов 1–7: вход — пакет этапа 7 (или N/A) плюс сведения этапов 1–6; выход — краткий отчёт пользователю и закрытие в `main`.

Без пакета этапа 6 (успех тестов) и без пакета этапа 7 (документы или N/A) этап 8 не начинают.

## Связь с tz-workflow

1. Обязательная цепочка — 8 этапов `tz-workflow`. Этот skill — только этап подготовки отчётов.
2. Git, коммиты и DoD — по `tz-workflow`, `commit-to-main`, `merge-to-main`. Закрытие ТЗ — здесь, не на этапах 5–7.
3. Этап 8 начинать **после** успешной проверки и написания документации (или N/A). Не закрывать при открытых дефектах или устаревшем help/руководстве.
4. Новые вопросы пользователю здесь не задавать: это этап 2. Не переписывать решения этапа 3 и не кодить. Рекомендации в конце отчёта — необязательные предложения, не новый пул задач.
5. Отчёт — артефакт хода в промпте / сообщение пользователю, не отдельный коммит «отчёта» в репозиторий. В `main` коммитят продукт и конфиг по правилам проекта.
6. Отчёт пишет только `lead`. Других агентов на этап 8 не вызывать.

## Кто пишет

Только `lead`. На этом этапе код и документы не правят.

Lead собирает уже готовые пакеты этапов 1–7. Не восстанавливать ход заново опросом пользователя.

## Содержание отчёта (обязательно, кратко)

Все секции короткие. Без логов, диффов и полного текста skills.

1. **Итог.** Что сделано; какие новые функции; какие проблемы возникли; что не получилось реализовать.
2. **ТЗ.** Само ТЗ от пользователя (суть, не дословная простыня чата, если ТЗ длинное — сжатая формулировка плюс отсылка к исходным пунктам).
3. **Вопросы и ответы.** Вопросы этапа 2, ответы пользователя или допущения lead. Вопросов не было — N/A.
4. **Решения.** Разработанные решения этапа 3 (по пунктам, без внутренних черновиков).
5. **Пул задач.** Задачи со статусами: выполнено / нет / были проблемы (и кратко какие). Не список файлов.
6. **Тесты.** Кратко: что тестировали `qa-tester` / `manual-tester` / `sql-tester` (или N/A), какие результаты. Детали прогонов — N/A, если они не меняют вывод.
7. **Документация и help.** Кратко: что сделал `technical-writer` (руководства, help, схемы для пользователя или N/A).
8. **Рекомендации (необязательно).** Что ещё можно было бы внести. Не блокер закрытия. Нет идей — секцию опустить или N/A.

## Действия lead

1. Проверить вход: этап 6 успешен; этап 7 готов или N/A.
2. Собрать отчёт по секциям выше. Статусы задач сверять с фактом проверки, не с самоотчётом этапа 5, если они расходились.
3. Отдать отчёт пользователю (Slack / чат — тот канал, где велось ТЗ).
4. Закрыть в git: коммит, merge в `main`, push `origin/main`. Задача не завершена, пока изменения не в `main`.
5. Пока отчёт не отдан и `main` не содержит работу — ТЗ не закрыто.

## Формат пакета этапа 8

Короткие секции (артефакт хода, не коммит отчёта в git):

- вход (пакет этапа 7 или N/A; успех этапа 6);
- итог (сделано / новые функции / проблемы / не реализовано);
- ТЗ пользователя;
- вопросы и ответы (или N/A);
- решения;
- пул задач со статусами;
- краткий отчёт по тестам;
- краткий отчёт по руководству и help;
- рекомендации (необязательно);
- git: ветка влита в `main` / push `origin/main` / хеш.

## Стоп-лист

- Не начинать этап 8 при открытых дефектах этапа 6 или неготовых документах этапа 7.
- Не повторять этапы 1–7 (приём, опрос, решения, пул, код, проверка, тексты пользователя).
- Не поручать отчёт другому subagent.
- Не раздувать отчёт логами CI, полными диффами и внутренними именами без нужды.
- Не выдавать рекомендации за обязательный объём работ.
- Не считать ТЗ закрытым без отчёта и без `main`.
- Не второй workflow вместо `tz-workflow`.
- Не коммитить текст отчёта как единственный артефакт вместо кода и документов.

## Антипаттерны

- Второй workflow вместо `tz-workflow`.
- Закрытие «тесты зелёные» без секций ТЗ / вопросы / решения / пул / тесты / docs.
- Статусы задач только из отчёта этапа 5 при расхождении с этапом 6.
- Простыня вместо краткого отчёта.
- Рекомендации как новый этап 4 без запроса пользователя.
- Lead не пишет отчёт и считает merge достаточным закрытием.
