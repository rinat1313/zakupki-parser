# Технические писатели

Skill **дополняет** `tz-workflow`. Не заменяет его. Не дублирует 8 этапов и не создаёт второй workflow. Пользователь группы — **subagent** в `.cursor/agents/`. `lead` вызывает его через Task на этапе документации.

## Когда включать

Lead читает этот skill на этапе **4** (отдельная задача зоны документации) и на этапе **7** (`tz-docs`, тексты, схемы, help). На этапах 1–3 роль не выбирает продукт вместо специалистов. На этапах 5–6 не пишет код и не правит продукт «заодно». На этапе 8 не подменяет отчёт.

Не основной сценарий для закрытия ТЗ: выход — актуальные руководство, help и схемы для пользователя (или N/A), не отдельный workflow.

## Связь с tz-workflow

1. Обязательная цепочка — 8 этапов `tz-workflow`. Этот skill — маршрут вызова технического писателя внутри этапов 4 и 7.
2. Git, коммиты и DoD — по `tz-workflow`, `commit-to-main`, `merge-to-main`.
3. Вызывай через Task: `technical-writer`. Не вызывай `tech-writer`.
4. Этап документации — `tz-docs`. Стиль слоёв — `user-docs`. Агент не заменяет эти skills.
5. На этапе 7 код приложения, CSS, API, БД и тесты **не** правят. Нет пользовательских изменений — N/A, не выдумывать разделы.

## Группа

| Роль | Агент | Что делает | Когда N/A |
|------|-------|------------|-----------|
| Технический писатель | `technical-writer` | Описывает функционал простым языком; переводит термины; схемы и презентации для пользователя; состав руководства и help | Нет пользовательского поведения, help и руководства не затрагиваются — N/A |

Роль обязательна к вызову на этапе 7, если в пуле есть задача на тексты. Нет зоны документации — N/A, не пропуск этапа 7 без пометки.

## Действия lead

1. На этапе 4 (`tz-tasks`): отдельная задача зоны документации с ролью технического писателя, если меняются визуал, логика или сценарии. Нет пользовательских изменений — не назначать роль.
2. На этапе 7 (`tz-docs`): Task на `technical-writer`; писать по пакету этапа 6 и фактическому UI, не по самоотчёту этапа 5.
3. Help и руководство — одни названия. Схемы — если без них сценарий непонятен.

Выводы роли — в пакет этапа 7 (короткие пункты или N/A), не отдельные файлы «отчёта писателя» в git.

## Стоп-лист

- Не заменять Task «линзой без агента».
- Не второй workflow вместо `tz-workflow`.
- Не писать docs на этапе 6 и не кодить на этапе 7.
- Не пропускать назначенную роль без N/A.
- Не подменять `tz-docs` и `user-docs`.
- Не спрашивать пользователя из этого агента.

## Антипаттерны

- Lead пишет гайд сам без Task, когда зона документации есть.
- Тексты на жаргоне реализации.
- Help копирует всё руководство в модалку.
- Схемы «для разработчика» вместо пользователя.
- Документация «заодно» в задаче на код.
