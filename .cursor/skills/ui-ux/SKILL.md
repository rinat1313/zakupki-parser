# UI/UX редактора схем

Skill **дополняет** `tz-workflow`. Не заменяет его. Не дублирует цепочку этапов и git.

При frontend/UI `lead` читает этот skill на этапах вопросов, решений, выполнения и проверки UI и передаёт его `ui-ux-designer`, `frontend` и `manual-tester`. Backend-only — не основной сценарий: достаточно краткой пометки N/A по UI. Вопросы пользователю задаёт только lead.

## Когда включать

Включай, если ТЗ затрагивает:

- HTML, CSS, JS;
- схему и холст;
- инспектор;
- справку (help);
- модалки и оверлеи;
- inline-редактирование.

Не делай этот skill основным для чисто backend/БД/API без UI.

## Связь с tz-workflow

1. Обязательная цепочка — 8 этапов `tz-workflow`. Этот skill работает внутри этапов вопросов, решений, выполнения и проверки UI.
2. Git, коммиты и DoD по `tz-workflow`, `commit-to-main`, `merge-to-main`.
3. Внутри этапов UI:
    - `ui-ux-designer` оценивает поверхности, темы, UX;
    - `frontend` реализует в HTML/CSS/JS;
    - `manual-tester` проверяет факты в браузере (клики и ввод, не один скриншот).
4. Актуальная справка — часть DoD (правило `update-user-help`). Руководство — skill `user-docs`.

## Карта поверхностей

| Поверхность | Назначение |
|-------------|------------|
| Topbar | сессия, загрузка/сохранение, выгрузка, проверки, темы, help |
| Обозреватель | дерево решения, выбор схемы по запросу |
| Холст | схема, выделение, движение объектов |
| Инспектор | свойства выбранного объекта, inline-поля |
| Модалки / оверлеи | диалоги, подтверждения, режимы поверх холста |
| Help | `#helpModal` / `#helpBody`, тексты из `App.showHelp()` |

## Стек

- Только HTML, CSS, JS.
- Точки входа: `web/index.html`, `web/css/app.css`, `web/js`.
- Новые UI-фреймворки не подключать.

## Стили и темы

- Цвета, отступы, типографика — CSS-токены и темы.
- Не хардкодить цвета в компонентах и инлайне.

## Инспектор

Следуй правилу `inspector-editing` (`.cursor/rules/inspector-editing.mdc`):

- inline-редактирование во вкладках сохранять;
- `IsLocked === 'True'` ограничивает только drag на схеме и поля **X / Y / Angle**;
- кнопка «Движение» / `schemeMovementLocked` — отдельный режим, не путать с `IsLocked`.

## Справка

- Тексты: `App.showHelp()` в `web/js/app.js`.
- Модалка: `#helpModal` / `#helpBody` в `web/index.html`.
- При смене визуала или логики обновляй help по правилу `update-user-help`.
- Без актуальной справки UI-задача не закрывается.

## Проверка в браузере

- Клики, ввод, навигация — не один скриншот.
- Темы (светлая/тёмная, если есть в UI).
- Empty и error.
- Связанные состояния: дерево ↔ холст ↔ инспектор.

## Антипаттерны

- Второй workflow вместо `tz-workflow`.
- Read-only инспектор без явного ТЗ.
- Массовая выдача всех схем решения на фронтенд.
- Устаревший help.
- Пропуск проверки в браузере.

## UX-чеклист редактора

- Сессия загружена до действий со схемой.
- Dirty / несохранённые изменения видны и не теряются молча.
- Контролы disabled, пока нет решения/схемы.
- Движение по холсту vs `IsLocked` vs режим «Движение» — раздельные ограничения.
- На фронтенд — только запрошенная схема, не всё решение.
