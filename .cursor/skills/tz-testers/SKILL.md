# Тестировщики

Skill **дополняет** `tz-workflow`. Не заменяет его. Не дублирует 8 этапов и не создаёт второй workflow. Каждый пользователь группы — **subagent** в `.cursor/agents/`. `lead` вызывает их через Task на этапе проверки.

## Когда включать

Lead читает этот skill на этапе **4** (пометки зон проверки в пуле) и на этапе **6** (`tz-verify`, прогон). На этапах 1–3 и 5 роли не заменяют проектирование и код. На этапах 7–8 не пишут docs и отчёт.

Не основной сценарий для закрытия ТЗ: выход — факты прогона и пакет этапа 6, не отдельный workflow.

## Связь с tz-workflow

1. Обязательная цепочка — 8 этапов `tz-workflow`. Этот skill — маршрут вызова тестировщиков внутри этапов 4 и 6.
2. Git, коммиты и DoD — по `tz-workflow`, `commit-to-main`, `merge-to-main`.
3. Вызывай через Task: `qa-tester`, `manual-tester`, `sql-tester`. Не вызывай `tester`, `ui-tester`.
4. Прогон — `tz-verify`. Тестировщики не чинят продукт: код приложения, конфигурацию, help и руководство **не** правят. Неуспех — разбор в `tz-verify`, переделка на этапе 5.
5. Manual опирается на skill `ui-ux` (ручной прогон UI), не вместо него. Исполнение кода — исполнители, не эта группа.

## Группа

| Роль | Агент | Что делает | Когда N/A |
|------|-------|------------|-----------|
| QA тестировщик | `qa-tester` | Тестирует код продукта; пишет автотесты и тесты конкретных функций | Нет кода приложения для проверки — N/A |
| Manual тестировщик | `manual-tester` | Тестирует приложение вручную (сценарии, UI, клики и ввод) | Нет запускаемого UI/клиента — N/A |
| SQL тестировщик | `sql-tester` | Проверяет работу баз данных и SQL-запросов | Нет БД, миграций, SQL — N/A |

Все три роли обязательны к вызову на этапе 6, если задача в пуле. Нет зоны проверки — N/A по роли, не пропуск всей группы.

## Действия lead

1. На этапе 4 (`tz-tasks`): у задачи зоны проверки — QA / manual / SQL (можно несколько). Нет зоны — не назначать роль.
2. На этапе 6 (`tz-verify`): Task на назначенные роли; чужие зоны не гонять без причины.
3. Во время прогона не править код продукта и документацию. Автотесты QA не подменяют починку.
4. Несколько ролей — lead вызывает каждую по очереди через Task.

Выводы ролей — в пакет этапа 6 (короткие пункты или N/A), не отдельные файлы в git.

## Стоп-лист

- Не заменять Task «линзой без агента».
- Не второй workflow вместо `tz-workflow`.
- Не чинить продукт на прогоне.
- Не пропускать назначенную роль без N/A.
- Не подменять этап 5 и исполнителей.
- Не спрашивать пользователя из этих агентов.

## Антипаттерны

- Lead сам объявляет прогон без Task.
- QA правит реализацию, чтобы автотест стал зелёным.
- Manual объявляет UI пройденным по скриншоту.
- SQL меняет схему или фикстуры «на всякий случай».
- Прогон заменён локальной проверкой этапа 5.
